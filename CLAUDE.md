# CLAUDE.md

Guidance for working in this repo. The product vision is in [key_features.md](key_features.md), what's built and what could come next in [ROADMAP.md](ROADMAP.md) (update it when a milestone finishes); setup and content conventions for humans are in [README.md](README.md).

## Commands

```sh
npm run dev        # dev server at http://localhost:5173
npm test           # vitest: date math + data integrity
npm run typecheck  # tsc --noEmit
npm run build      # typecheck + production build to dist/
node scripts/shot.mjs out.png [w] [h] [actions] [light|dark]   # screenshot the dev server in Edge
node scripts/openbible.mjs [--write | find <text> | show <name>]  # check places against OpenBible.info
node scripts/bsb.mjs [--refresh]   # rebuild src/data/bible/ (the BSB text, one JSON per book)
node scripts/cliopatria.mjs [--refresh]   # rebuild src/data/borders/cliopatria.json (empire outlines)
```

- Windows, PowerShell 5.1. Node is installed at `C:\Program Files\nodejs`; shells started before the install may not have it on PATH. In Git Bash, prefix commands with `export PATH="/c/Program Files/nodejs:$PATH" &&`.
- Before committing, gate on `npm test`'s exit code, not on grepping its output. Any failure blocks the commit.
- `npm test` runs Vitest through `scripts/vitest.mjs`, which restarts it from an upper-case drive letter. When the working directory is `c:\...` (VS Code terminals and Claude Code's shell often are), plain `vitest` loads itself twice and every suite fails at its first `describe` with `TypeError: Cannot read properties of undefined (reading 'config')`. Call `npm test`, not `npx vitest`. This was the "flake" of 2026-10-27/28: it came and went with the shell's drive-letter case, not with screenshots or caches.
- Map labels: MapLibre places symbols from the top layer down, so the layer that must win collisions (the focus event's places) goes last in `EventLayer`.
- `scripts/shot.mjs` (playwright-core driving the installed Edge; the dev server must be running) is how UI changes get checked; its header lists the actions (`mode`, `select` via Browse, `zoomIn`, click, hover, drag, `tap` at phone widths, eval…); `QUERY="?event=exodus"` opens a link. Its `select` skips Browse's "Filter: …" suggestion rows. Save screenshots outside the repo. Driving the app: don't `import()` app modules in `eval` (that loads a second store, which the app ignores); use the UI. At phone width, `select` via Browse can fail to select; pick from the Nearest events list instead.
- On Windows, stopping a background task doesn't kill the Node process behind it. Free a port with `Get-NetTCPConnection -LocalPort 5173` + `Stop-Process`.

## Architecture

- Static React 19 + TypeScript + Vite + Tailwind v4 site. No backend; all content is JSON in `src/data/`, validated with zod (`schema.ts`) and checked for broken links by `validate.ts`.
- `src/state/store.ts` (zustand) is the single source of truth: `currentYear` (fractional astronomical year), `pxPerYear` (time zoom), `selection`, `mode`, `chronologyId`. Timeline and map only read and write the store; they never talk to each other.
- `src/lib/`: `dates.ts` (year math and formatting), `entities.ts` (cross-entity queries), `journeys.ts`, `activeEvents.ts` (which events the map shows), `timeScale.ts`. Event order and parent/child links live in `entities.ts` (`eventsInOrder`, `eventOrderKey`, `adjacentEvent`, `parentEvent`, `childEvents`, `journeyOf`).
- The timeline is virtual: no native scrolling. Gestures change `currentYear` directly, and the cursor is fixed at the vertical center. Native scrolling can't reach day-level zoom across thousands of years.
- Map: MapLibre GL 6 via `react-map-gl/maplibre`, on OpenFreeMap tiles stripped down to relief and water (`baseStyle.ts`). Terrain is a MapLibre hillshade from AWS open-data Terrarium elevation tiles (no key; the `elevation-tiles-prod.s3.amazonaws.com` host sends CORS headers on GET, not HEAD), over a faint Natural Earth colour wash that's only sharp to zoom 6. Modern roads, labels and OSM land cover are left out; land cover is today's land use, mapped unevenly by country. Its worker URL must be set explicitly (`setWorkerUrl` in MapView), and `mapLib` must be passed so only one MapLibre instance exists.

## Data conventions

- Years are astronomical: 1 BC = `0`, 1446 BC = `-1445`. Never display a year 0.
- Optional `month`/`day` are approximate Julian placement; `label` keeps the biblical form ("14 Nisan"). Precision comes from which fields are present; there is no separate precision field.
- Dates are keyed by chronology id (`early`, c. 1446 BC, is the default, agreed with the user; `late`, c. 1260 BC, holds alternates); a missing entry falls back to the default. The chronologies differ only on the Exodus, so only dates before Saul need a `late` entry. Before the oppression in Egypt, `late` is `early` plus 186 years (1446 − 1260 BC), keeping Genesis's ages and the 430 years in Egypt (Exodus 12:40): Jacob goes to Egypt c. 1690 BC, in the Hyksos period late-daters cite; the patriarchs era's note says late-daters usually give only a period, and mentions the Septuagint's 215 years. The oppression through the judges has its own late dates. Readers choose in Settings, or with "Use this date" beside an event's alternate date (shown only where it differs); the choice is remembered per browser, and switching keeps the same event under the cursor (`setChronology`). Links carry `chron=late`; opening one applies it for that visit only, and a link with a year but no `chron` means the default.
- Kings follow Thiele's chronology (division 931 BC, Samaria 722, Jerusalem 586). Jesus is born c. 6–4 BC and crucified in AD 30; mention AD 33 in a `dateNote` where it matters.
- Non-narrative books are events of their writing or ministry, not of their contents: Revelation is John's vision on Patmos (c. AD 95), prophets are dated by their ministry, letters by when and where they were written. Don't date prophetic visions as history. Psalms is "David's psalms", within his reign (the book grew from Moses to the exile, said in its note); Proverbs, Ecclesiastes and Song of Songs are one event, "Solomon's wisdom", within his. Job is narrative: his story is placed, date unknown, in the patriarchs' time.
- **Quoting Scripture:** summaries, notes and tour narration quote the Berean Standard Bible word for word, the text the details panel shows, keeping its capitals ("LORD", "I AM WHO I AM", "My Father's house"); prose around a quote keeps lower-case pronouns for God. Words in capitals inside quotes are set in small capitals (`Prose`, `smallCaps` in `ScriptureText.tsx`). Every Scripture reference must be a real BSB passage (`bible.test.ts`).
- Region outlines in `regions.json` are the shapes of places: each feature id must match a location id. They're drawn beneath the base map's water, as the empires are, so a coast can run offshore and the real one trims it (`REGION_ANCHOR` marks where the app's labels start, above the base map). Egypt is the land, not the power: the Delta, the Fayum and the Nile valley to Aswan, without the deserts. Canaan follows Scripture's borders: Sidon to Gaza (Genesis 10:19), south to Kadesh-barnea and the Brook of Egypt (Numbers 34:3–5), west of the Jordan; Lebo-hamath, further north (Numbers 34:7–9), is disputed and left out. The place filter uses these outlines, so check which places fall inside after redrawing one. Regions are places, not powers: a land's name is timeless (Acts 13:19 still names Canaan), so they stay selectable at any time, and events point at them. The powers over a place change: each place's panel lists them under "Ruled by" (`RuledBy.tsx`, `rulersOver`: every outline that held its point, empires and Israel's own states alike, by stretch, named as on the map; adjacent ones with one name merge, Saul's Israel into David's; the tribes' are "Benjamin's allotment", since Jebus stood in Benjamin's until David). On the map a region's label shows only while something uses it (an event nearby, the selection or the focus event), so CANAAN doesn't sit on the map in AD 20.
- **Borders** (`src/data/borders/`, `lib/borders.ts`) are powers' outlines over time, kept apart from `regions.json`. `cliopatria.json` is generated by `scripts/cliopatria.mjs` (its `POWERS` table says which Cliopatria polities make each empire; the first and last snapshots stretch to the empire's dates in `empires.json`); never edit it by hand. A power's polities are merged into one shape (`polygon-clipping`, a dev dependency of the script only), so "Egypt divided" has no line through it. Two powers shouldn't hold the same land at once: where Cliopatria or a stretched snapshot says they do, fix it in `POWERS` against history (`from`/`to` to the year of a conquest, `yieldTo` to cut one power's land out of another's), and where one ends the year the next begins, the next gets the year. The script prints any overlap left; it should print none. The map shows rule, not overlordship (agreed with the user, so it isn't bogged down in technicalities): Egypt's kings were overlords of Canaan's city-states (c. 1550–1150 BC), which is told in words (the New Kingdom's and Canaan's summaries), and Egypt's and the Hyksos' outlines stop at its frontier (`beyond` in `POWERS`); Judah stayed a kingdom while it paid Assyria and Babylon tribute (2 Kings 18:14, 24:1), so their outlines yield to it until 586 BC (`yieldTo` can name drawn.json's powers). Israel's tribes and kingdoms count as powers under "Ruled by" like the empires. A power that governed a province directly (the Ptolemies in Judea) keeps it in its outline. The only lighter outline is the lands subject to David (`subject`), which Scripture claims (2 Samuel 8). Egypt is never blank: in the Second Intermediate Period (c. 1650–1550 BC) the Hyksos hold the Delta and Thebes the south ("Egypt (Thebes)", part of the Hyksos period's empire entry). `drawn.json` holds what Cliopatria lacks or gets wrong for us (its Israel ends in 701 BC and its Judah too): Ur, the tribal allotments, Saul, David and Solomon (with the lands "subject to Israel", `subject`), Israel and Judah, Yehud, Herod's sons, Agrippa I, the province of Judea, and Israel's neighbours Ammon, Moab, Edom and Aram. **Israel's neighbours** (Philistia, Phoenicia and the Nabataeans from Cliopatria, Ammon, Moab, Edom and Aram drawn) open their land as a place (`links` to a `location`: Moab, Arabia for the Nabataeans), not an empire entry, so the World history lane stays uncrowded; they share one slate hue (`tint: "neighbour"`). They follow the same rule as Judah: a kingdom that kept its kings under Assyria or Babylon stands until it was ended, and the empires yield to it; none is drawn while subject to David and Solomon (the "Subject to Israel" outline covers them), and the drawn ones leave out Israel's outlines of the time (they were generated with polygon-clipping, so redraw them the same way). Cliopatria's Philistia is cut to the five cities' coastal plain and its Phoenicia to the coast north of Carmel (`within`, since Cliopatria spreads them over half of Canaan and the colonies), with a strip along the coast for Tyre's island (`coast`). Assyria takes Israel's drawn land from 732 BC (`takes`), since Cliopatria's Assyria holds it only from 700. A place an outline on the map links to gives up its own dot and background label while the outline names it (`useNamedPlaces`), so MOAB isn't named twice. Place panels show "Borders on the map" too. Each outline shows from `from` until `to` (astronomical years, `to` excluded; `lateFrom`/`lateTo` for the late chronology), has a hand-picked `label` point inside it, and a drawn one always has a `note` saying how rough it is. Ids before an `@` name the power; one power's snapshots never overlap (`data.test.ts`). Selecting an outline opens its `empire`, else its first `links` entry; selecting any of them (Saul, or the United Kingdom era, for Saul's kingdom) shows it strongly and frames it. The tribes' allotments belong to "The land divided among the tribes" and start with it; they get no timeline bar (the World history lane is for foreign powers, and the Judges era covers them). Outlines sharing a note are named together under "Borders on the map". Coasts can run offshore: outlines are drawn beneath the base map's water.
- Don't invent precision Scripture doesn't give. Leave journey stops untimed rather than guessing days, and mark uncertain dates and sites as such, with a note. Where scholars disagree on an undated book, place it at the majority view and give the other date in its `dateNote` (Joel after the return, Obadiah after 586 BC).
- Letters list where they were written first, then where they were sent; a letter written during one of Paul's journeys is `partOf` it and marks the stop at its first place (`stopIndexOf`). Events along a journey are matched to stops in date order, each to the next stop at its place after the previous event's, so a place the route passes twice (Troas on the third journey) gets the right visit. Galatians stays apart, written after the first journey on a disputed date.
- `partOf` links an event to the larger event it happens within (Red Sea → Exodus). Children stay full events (type, people, Scripture); one level deep; the date's midpoint falls within the parent's, and a parent's journey must have a stop at one of the child's places (`validate.ts`, `data.test.ts`).
- **People lanes:** each person has a `lane` (`people`, the main figures, called "Important people" in the menu, by default; or `kings`, `prophets`, `church`, `world`), plus any others they fit in `alsoIn` (Peter and Paul: church; Moses, Samuel, Deborah: prophets; Saul, David, Solomon: kings). They show once, in the first shown lane they belong to (`shownLane`), so turning on only the church lane still shows Peter; but kings always show in the Kings lane too (`shownLanes`), since there the bar is a reign in an unbroken line, so David can show twice: his life with the main figures, his reign among the kings. Birth and death marks go only on lifespan bars (`hasLifeMarks`). The timeline shows the lanes chosen in the Lanes menu (only `people` by default, remembered in localStorage), and selecting a person in a hidden lane shows it. A bar is the person's `dates` (a lifespan where Scripture gives one, else a reign or ministry, said so in `dateNote`), or, dashed and lighter, the span of their events ("known c. …", `personSpan`) for people in two or more events and prophets. Don't type in dates that only restate their events.
- **Who gets a person entry:** anyone in two or more events, or with a book named after them or written by them, and every king of the united kingdom, Israel and Judah: an exception to the rule, since a line of succession is worth seeing whole, kept as people rather than reign events, which would crowd the event lane (Thiele's dating; lifespans for Judah's kings where Scripture gives their age at accession). In the Kings lane a king's bar is his sole reign (`reign`, when it differs from `dates`; a coregency is told in `dateNote`), so reigns follow on without overlapping (`data.test.ts`): Judah (after the united kingdom) has the left column, tinted warm, Israel the next, tinted cool (`kingdom`); every king there has a `kingdom` (`data.test.ts`). Foreign rulers who act on Israel or the church (Sennacherib, Darius I, Augustus, the Herods, Pilate, Felix, Nero…) are the same exception, in the World history lane (`lane: "world"`, with the `empire` they ruled or ruled for; Rome's client kings and governors are Rome's), dated by their reigns from history, and listed on the events where they act; so are rulers between the Testaments who shaped Judea's story (Alexander, Antiochus IV). Earlier enemies dated only by their one event (Eglon, Sisera) are left out. Kings sharing a name are "Ahaziah of Judah", "Ahaziah of Israel"; Tibni, Omri's rival, is left out. A person gets a lifespan bar only when Scripture supports one; prophets whose lifespans aren't known (Jeremiah, Ezekiel) are dated by their years of ministry.
- Coordinates follow OpenBible.info (CC BY 4.0, credited on the map and in the README). Each location records its OpenBible place in `openbible` (`"Rephidim#2"` when we keep a candidate other than OpenBible's first, usually the traditional site, and say so in a note). Run `node scripts/openbible.mjs` after adding places; it should print nothing. Region, sea and wilderness points are map label positions and aren't checked. Region outlines are still hand-drawn.

## Design decisions (agreed with the user)

- **Selecting moves time only when needed.** Events jump to their moment. People and eras move the cursor only if it's outside their span, to the nearest edge. Places never move time. Selection never changes zoom.
- **No "Show on…" buttons.** Each view shows a "Show ‹name›" chip, with an arrow toward the selection, only while the selection is out of frame; clicking it centers and fits (timeline) or re-frames (map). The details panel offers "Open on map/timeline" only when that view is hidden, and "Replay journey" for events with journeys.
- **Event popup on the map** for the focus event when it isn't the selection (the details panel covers that case). It never moves the map: it sits beside the visible part of the event, avoiding the event's own places, labels and route and the map's controls (`data-map-obstacle`), or at the nearest edge with an arrow when it's all off screen. Events with no places get no popup. Its × (or Escape with nothing selected) quiets the map: no focus event at all (no popup, journey, region outlines or marked row in Nearest events) while the reader scrubs or zooms, to watch the empires change, say, until they do something with an event: select one, step to one (Nearest events) or press play. Selecting a place, person or empire and closing it leaves the map quiet; closing a selected event doesn't quiet it (the nearest event's popup shows again). While quiet, Nearest events says "Events hidden on the map · Show", so the quiet map never looks broken. Phones get no popup: the collapsed Nearest events row does its job.
- **One focus event on the map:** the selected event, or else the nearest event to the cursor (among a selected place's events). Only it draws a journey and region outlines; other nearby events show as place dots. While a person, empire or era is selected there's no focus event (no popup, journey or marked row in Nearest events, unless the reader steps to one there): the map shows the selection's places, so a nearby event never reads as the selection (Herod's reign ends beside Jesus' birth).
- **Events within events** (`partOf`), chosen over merging them into journey stops so each keeps its type, people and Scripture: they fold into the parent on the timeline until it draws as a bar, sort right after it, label their stop on its route, nest under it in Nearest events, and the details panel shows "Part of" (child) and "Along the way" (parent). Selecting one keeps the other lit (not dimmed) on the timeline.
- **Journeys:** direction arrows, legs that share any stretch of road (the same two points, stops or `via`, either way) drawn side by side (line-offset), so a partial retrace like Egypt and back to Nazareth counts, a moving head dot while drawing, merged stop numbers ("4·6"), shown as the line reaches each stop. Each stop marker is one image, disc and number drawn together (`stopImage.ts`, made on demand through MapLibre's missing-image resolver), with later stops on top: MapLibre draws all of a layer's circles before any of its text, so circle-plus-text stops showed their numbers through each other. Legs are straight between stops unless the stop lists `via` points (unnumbered), which keep sea legs off land and land legs on the old roads; describe the lane a route takes in a stop `note` when Scripture names it ("under the lee of Cyprus"). Place dots sit beneath the route so stop numbers stay visible. Places nothing uses (grey dots) show only from zoom 5.5, with their labels (`BASE_DOT_ZOOM`); further out Israel's dozens of dots piled into one blot. Clustering them into count bubbles was rejected: a count says nothing to a reader, and the places in use (the nearest events', the selection's) must always show on their own. Events along a journey (`partOf`) label their stop once the route reaches it; selecting one draws its parent's route up to its stop, with that stop ringed. Map labels: MapLibre places symbols top layer down, so the order is stop numbers, then the event's own place labels (beneath `JOURNEY_STOPS_LAYER`; they try 8 positions around their dot and may cross the route rather than vanish), then invisible clearance marks along the route, then background place labels and region names (beneath `JOURNEY_BASE_LAYER`), which keep clear of all of it.
- **Dates stand at the middle of their precision** (`specExtent`): "1446 BC" is mid-1446 and "4th month" is mid-month, for moments and for both ends of spans and lifespans, on the timeline and in date order. So a span "from 1446 BC" starts level with a moment that year, and a death "in 1405 BC" sits at the end of that person's bar. Date bounds for "is the cursor within it" (`specBounds`, eras) still cover the whole year.
- **Date order** (`eventsInOrder`, used by lists, step buttons and play): by where the event starts (`specExtent`). On ties a parent comes before the events within it, then the file's order stands, so put events sharing a date in the order Scripture tells them (much of the Gospels is dated only to the year). So the burning bush comes before the plagues (both 1446 BC), and a long span like the wandering comes right after it begins, not among the events in its middle.
- **Births and deaths:** a birth or death event is about its first listed person, and its date must match that person's lifespan (`data.test.ts`). Routine ones (not `major`) are drawn as small marks at the ends of the person's bar instead of event dots, unless the people lane is hidden or the event is selected (`lifeMarkPerson`); the ones the story dwells on (Moses' death, Jesus' birth) are `major` and stay dots.
- **Play** steps through events one by one, resting longer while a journey draws. It doesn't sweep time linearly.
- **The map shows the 5 nearest events** to the cursor (`NEAREST_COUNT` in `activeEvents.ts`), whatever the time zoom. Time zoom affects only the timeline, so the map has no time-zoom controls. The panel is titled "Nearest events" and lists dates, because in quiet stretches the nearest event can be years away. Distance is the gap to the event plus 1/20 of its length, so a specific event beats a long span that covers the cursor (Moses flees over a century of slavery), while the span wins when nothing specific is within a few years. The list always holds the selected event (or else the nearest) with the events just before and after it (`adjacentEvent`, the same order as the step buttons), so it doubles as a way to step through events, and the event it's part of, so it stays nested while the cursor travels to it; the nearest fill the rest. The list keeps date order: a child is indented only right under its parent or a nested sibling; with another event in between (Hebrews between the Jewish revolt and AD 70) it stays flush and says "in ‹parent›". Collapsed, the panel shows just the focus event; on phones it starts collapsed in Both view and open in Map view. Dragging the list up or down steps one event per 28px (up is later, as on the timeline): with an event selected each step selects the next, otherwise the cursor jumps (no glide, which would pass other events) to it and it becomes the focus while the cursor stays there (`focusHint`, `stepTo`), since events sharing a moment (Jesus' ministry and baptism) can't be told apart by the cursor. The whole panel, header included, is the drag surface (so a drag starting just off a collapsed panel's one row still steps); it's `touch-none` and also cancels native `touchmove`, since not every mobile browser honours `touch-action`, so the list doesn't scroll by touch.
- **Phone details sheet** opens as a short peek (kind, title, date, start of summary); tap or swipe up to expand, swipe down or tap the handle to shrink. It keeps its size as the selection changes (so play doesn't cover the map), and it always stops above the bottom controls: mark any control it must not cover with `data-sheet-floor`. In Both view on a phone, the timeline and map split the space that's actually visible: the timeline is (height − time strip − peek, while something is selected) ÷ 2 (`--below-map` in AppShell, `timeStripPx` in the store, `PEEK_HEIGHT`), so the map isn't mostly covered by the peek. In Timeline view on a phone, the timeline's controls move into a solid bar along the bottom (like the map's time strip), so the sheet rests on a bar instead of floating buttons with the timeline showing around them.
- **Crowded timeline:** spans shorter than 14px draw as dots (a shorter bar is hard to click). Dots too close to stack sit side by side in time order, at most 5; the rest fold into a "+N" badge that zooms in until they spread out. Which dots stay and which labels win is ranked: selected, then highlighted, then `major` events (a flag in `events.json`), then earliest. All labels, span labels included, sit in one column after the dots, so a label never covers a dot. A span's label slides down its bar when its start is taken. Events with `partOf` fold into their parent (hidden) until the parent is long enough to draw as a bar, unless selected. Hovering a span's bar or its label highlights both (`group/event`), as hovering a dot's label highlights the dot.
- **Shareable links** (`lib/shareLink.ts`, `state/urlSync.ts`): `?event=exodus&year=1446.3BC&zoom=2.78&view=map` (or `person`, `place`, `era`; years as written, with the fraction of the year after the point; the default Both view left out). The address bar always holds the current link, replaced (not pushed) 300 ms after things settle, so Back leaves the app. The link keeps the year only while the selection is in view on the timeline; scrolled away from it, the year is left out, so opening the link goes where selecting would and the reader sees what was shared. Places (no moment of their own) and no selection always keep it. Opening one selects instantly (no glide), then the link's year wins; the map frames a selection made before it loaded. The details header has a Share button: the share sheet on touch screens, otherwise copied to the clipboard. Keep the parameter names stable: links end up in lesson notes. Passage links (`?passage=Exod.12-14`) wait for filters, since a passage is a filter that lights every matching event.
- **Filters** (`lib/filters.ts`, `components/Filters.tsx`) hide events, and only events: people, places and eras stay, since lanes already choose which people show and the bars give context. Event types (any of those chosen), people (events involving any of them), books or passages (events whose Scripture shares a verse with any of them, `lib/passages.ts`), eras (events whose midpoint falls in one, so the check takes the chronology) and places (events at the place, on a journey through it, or for a place with an outline, at a place inside it: Canaan includes Hebron); each kind in use must match. Hidden events leave the timeline, the map, Nearest events, step, play and "Before and after"; routine birth and death marks follow too, and a child whose parent is hidden no longer folds into it. A selected event always shows, filtered or not. While Births or Deaths are filtered to, routine ones are event dots with labels, not marks on bars (`drawnAsLifeMark`). With nothing selected, people stand out and the rest dim (`filteredPeople`): the people filtered to, or with only types filtered, everyone in a shown event (Judgments lights Noah). Filtering to someone in a hidden lane shows that lane. The people, place and passage pickers are comboboxes (`Picker`): the first match is highlighted, arrows move, Enter picks; the passage picker offers what's typed, if it parses ("Exodus 12–14"), then books it starts. The Filter button beside Browse opens the choices; while any are on, a chip bar under the header says what's shown, so it's always clear why events are missing. Browse still lists hidden events, dimmed ("Hidden · date"), and offers "Filter: show only …" rows when the search names a type, exactly one person, place (by its own name) or era, and when it reads as a book or passage ("Job" offers both). Under All, a search matches tours by title only. Event, person, era and place panels end with a "Show only …" toggle ("battles", "David's events", "events in the Judges", "events at Jerusalem"). Links carry them (`&types=battle,miracle&people=david&passage=Exod.12-14,Matt.5-7&eras=judges&places=jerusalem`). **`?passage=` is the reading-plans app's contract:** OSIS book ids (`Exod`, `1Kgs`, `Ps`), `.` between chapter and verse, `-` for ranges (`Gen.12.1-9`, `Exod.12.1-14.31`), commas between passages; the parser also takes what people type ("Exodus 12:1–14:31", "II Kings 2"). Keep it stable. A filtered link with no year or selection starts the cursor at the first event it shows. **Filters move time only when needed:** adding one (anywhere: panel, Browse, detail shortcuts) glides to the nearest match, but only when nothing is selected and no match is on screen; removing one never moves time. Theme tags (covenants, prophecy fulfilled…) were dropped: the user doesn't want them, and event types cover the useful part.
- **Scripture in the app:** each reference under Scripture opens its text inline, in the Berean Standard Bible (public domain since 2023, chosen over the ESV, whose free API has rate limits and forbids storing the text, and over the WEB, which reads stiffer). The text is bundled, one chunk per book (`src/data/bible/`, built by `scripts/bsb.mjs`, loaded by `lib/bible.ts`), so it works offline with no key. Passages over 6 verses start cut short with "Read more"; verses the BSB omits (Matthew 17:21) are skipped; chapter numbers mark where each chapter starts in a passage over several. Each passage links out to the ESV on Bible Gateway, which many readers' churches use ("View on Bible Gateway"). Jesus' words are in red by default (a Settings choice, `redLetters`): `bsb.mjs` takes the words from the plain text and wraps the stretches the BSB's USFM edition marks (`\wj`) in braces, which the BSB never uses; `verseParts` splits them out, and a verse's `text` stays plain.
- **World history** (`empires.json`, `world` events, `lane: "world"` rulers): an optional lane, off by default, at the far left of the timeline, tinted stone. It holds the great powers as square-ended bars (`EmpireBars`; Egypt's line in one column, Mesopotamia's in the next, Rome's in the next, via `column`), their rulers' reigns beside them, and, in the event lane, world events (`world: true`: Hammurabi's laws, the Sea Peoples, Qarqar, Nineveh falls, Marathon, Pompey, the fire of Rome, AD 70…) as squares with muted italic labels, so history never reads as Scripture. While the lane is off, world events are hidden everywhere (timeline, map, Nearest events, step, play), like a filter that isn't shown as one (`Filters.world`, kept in step with the lane by `setLaneShown`; `NO_FILTERS` leaves it out so clearing filters keeps it); Browse lists them as "World history · date", and selecting one, or an empire, turns the lane on. Empires are their own kind (`?empire=assyria`): selecting one moves time as an era does, and its panel lists where it was ruled from, its rulers, and its events (its rulers' events, and world events at its capitals while it stood); in Browse they're under Eras. History's dates don't move with the chronology, so world entries have only `early` dates, and each world event's `dateNote` names its source (Josephus, the Babylonian Chronicles, Tacitus).
- **Empires on the map** (`BorderLayer.tsx`): the great powers and Israel's own states as they stood at the cursor's time, as faint fills with a line, from Cliopatria (CC BY 4.0, credited on the map and in the README) plus Israel drawn by hand. Outlines change in steps at each dated snapshot, never morphing (that would invent borders), with a short cross-fade of the ones that changed. An "Empires" toggle beside "Modern borders" turns them off (on by default, remembered per browser); the selection's outlines (an empire's, or the person's or era's an outline links to) show strongly either way, and selecting one frames its land. Each line of powers keeps one hue (Egypt's kingdoms gold, Rome wine), Israel's take the Kings lane's tints (Judah warm, Israel cool, the united kingdom plain). Labels are the lowest symbol layer, so every place and region label wins; a power named like a region place (Egypt) leaves the naming to the place while the place's label shows (only while something uses it), and names itself otherwise. Every outline stays in the source; fades set each one's opacity as feature state (`o`) every frame. Don't fade by changing a layer's filter or paint: a new filter waits for tiles to rebuild while the old ones draw with the new opacity, which made outlines flash (Ur reappearing as Babylon rose). Hover and click go through an invisible `borders-hit` layer filtered to what's shown. Hovering a label shows its name and dates, and so does resting a mouse inside its borders for 0.8 s (`REST_MS`; never while dragging, and places, journeys and labels win); clicking either opens it. Hover strengthens the outline but never changes the label, which would make MapLibre re-place it out from under the pointer. The notes, and Cliopatria's credit, are in the details panel of whatever the outlines belong to ("Borders on the map", `MapBorders.tsx`).
- **Settings** live in a gear menu at the right of the header (`SettingsMenu.tsx`): theme (System, Light, Dark), years (BC/AD or BCE/CE), the words of Jesus (in red or plain) and the date of the Exodus (early or late), each remembered per browser. Its icon is a gear, not rays, which read as the theme's sun.
- **Escape closes one layer per press**, wherever the focus is: an open menu (Filter, Settings: they catch it first, capture plus `stopPropagation`), then Browse, then the selection, then the map's event popup (`escape` in the store, one listener in AppShell; the popup hears `escapeNonce`). Browse can stay open under the Filter and Settings menus (filtering updates its dimmed rows live); on phones, where Browse covers the screen, opening a menu closes it. A chosen theme sets `data-theme` on `<html>`, which the CSS colour tokens follow (a small script in `index.html` applies the saved one before first paint); code that needs to know uses `useIsDark()`, never the media query directly. The phone header is tight: it fits at 360px only with Browse and Filter as icons and the spacing below 400px; check that width when adding to it.
- **Guided tours** (`tours.json`, `TourBox.tsx`, `tour` in the store): each step selects an event (so time and the map move as selecting does, and journeys replay), and the step's narration sits at the top of the details panel with Back, Next (Finish on the last) and ×. Tours are listed in a Tours tab in Browse, first in All, and the welcome card points to them. Selecting something else pauses the tour ("Tour paused · Resume"); clearing the selection (Escape, ×) ends it, but the step reached is remembered per browser (`tourProgress`) and Browse offers "Continue · step 5 of 12" and "Start over"; Finish on the last step forgets it. Tours are listed in story order. On phones the narration clamps to two lines in the peek. Links carry `tour=exodus&step=3` (from 1), only while the step's event is selected. Steps run in date order in both chronologies (`data.test.ts`); narration ties each event to the story rather than repeating its summary.
- **Family tree** (`FamilyTree.tsx`, `lib/family.ts`, `lib/familyLayout.ts`): its own view over the timeline and map (the details panel stays beside it), opened from a person's Family section ("Show in the family tree"), Browse (a row at the top of People; a search also finds the genealogy names) or a link (`tree=obed`, kept stable); Escape closes it after Browse. It shows the whole family of the person or name it's centred on, top to bottom like the timeline, with their line (every ancestor, through both Gospels' lines) in the accent colour. People's `parents`, `altParents` and `spouses` can name **genealogy names** (`genealogy.json`): the people of the genealogies with no events (Seth to Lamech, Shem to Nahor, Jacob's other sons, Perez to Obed, Matthew's and Luke's lines after David), which get no person entry, bar or Browse row (so the who-gets-an-entry rule holds) but have their verses and a note; ids are readable and unique across people and names (`luke-matthat-24`, `matt-jacob`). Matthew's and Luke's lines from David to Joseph are both drawn (agreed with the user): Matthew's through Solomon and the kings (the kings' own line, which Matthew 1:8 and 1:11 shorten), Luke's through Nathan, meeting at Shealtiel and Joseph, where the other Gospel's father is an `altParents` link, dashed; notes give the usual explanations (Luke gives Mary's line, or one line is by law). Other differences are notes, not nodes (Luke's Cainan, Admin and Arni, Sala). Jesus' parents are Mary and Joseph, with a `familyNote` that Joseph was his father by law; his brothers are taken as Joseph and Mary's sons, with the Catholic and Orthodox readings in their `familyNote`. Parents link through a union point (a couple, or a lone parent), so siblings hang together; spouses with no children here still get one. Dagre (`@dagrejs/dagre`, loaded only with the tree) lays it out; ranks follow edges, not generations, so Luke's longer line stretches Matthew's beside it. Clicking a person selects them (the tree follows any person selected elsewhere, if they have family); clicking a name centres the tree on it and shows its card (at the top on phones, where the details sheet covers the bottom). Dragging pans, the wheel pans and Ctrl+wheel or a pinch zooms. Families not joined to the main one (Peter and Andrew, the Herods, Jehu's dynasty) are trees of their own.
- Hover cards are custom and instant; never rely on the browser's `title` tooltip. Touch gets none: the map ignores the mousemove browsers make up after a tap, and a click clears the card, since the details panel names what was clicked. An event panel's kicker is its type ("Battle", "World history · Battle", `eventKind`), as in the timeline's hover card. The two overview bars (the timeline's right edge, the map's time strip) name the era under the pointer (`EraTip`) while hovering with a mouse or dragging with any pointer, so scrubbing on a phone says where it is.
- Approachable for lay readers and small groups; honest about uncertainty without being academic.

## Open questions and known issues

- On the map, a child event's stop label can nearly repeat the place name ("Crossing the Red Sea" beside "Red Sea crossing (Yam Suph)?").
- "The twelve spies" isn't `partOf` anything: "Israel leaves Sinai" is a single date, not a span covering the journey to Kadesh.
- Seven events have no places, so they get no map popup or dots: Creation, Birth of Ishmael, Birth of Jacob and Esau, Job's trials (Uz can't be located), and the writing of Matthew's Gospel, Hebrews and Jude (where they were written isn't known).
- With the World history lane on, phones have little room left for the event lane (as with the Kings lane): the lanes' widths are fixed by their busiest stretch.
- At the map's closest framing (zoom 7.5), places a few hundred metres apart in Jerusalem (Golgotha, Gethsemane, Moriah) hide each other's labels.

## Working style

- Commit each logical change with a clear message, and push after committing (the user has OK'd pushing without asking).
- Small fixes and single-commit changes go straight to `main`. Larger or experimental features that take several commits get a short-lived branch (`feature/<name>`), which is merged into `main` and deleted when done. Since `main` deploys publicly, the user reviews a branch on its preview URL before it's merged; send them the link.
- Deployment: a Cloudflare Worker that only serves static files (`wrangler.jsonc`; Cloudflare calls Pages legacy, so we chose Workers) builds every push (`npm test && npm run build`, then `npx wrangler deploy`; Node from `.node-version`). `main` is public at bible.rector.app, so anything pushed to `main` goes live; other pushed branches get private preview URLs behind Cloudflare Access (see README), at `https://<branch, with / as ->-bible-timeline.logan-rector.workers.dev` (e.g. `feature-journeys-bible-timeline…`); `gh api repos/loganrector1/bible-timeline/commits/<sha>/check-runs` shows whether a build passed. Branch builds run `wrangler preview`, which fails unless `wrangler.jsonc` has a `previews` block. Tests run on Linux there, so don't make them depend on Windows paths or on the network.
- Verify UI changes in a real browser (screenshots at desktop and phone widths, light and dark), not just by type-checking.
- Ask before making product or design calls the user hasn't decided; recommend an option.
- Keep this file current: when a decision is made, a convention changes or a new gotcha turns up, update CLAUDE.md in the same commit as the change.
